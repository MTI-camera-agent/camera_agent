# Research: real-time multimodal camera-coaching products

## Summary

ChatGPT Voice with video, Doubao video calling, and Gemini Live converge on a useful interaction model: make visual availability explicit, preserve a continuing objective, let new user actions preempt old work, expose meaningful state, and ground advice in what is currently visible. The camera agent should adopt those principles but not imitate the products’ apparent continuous, full-duplex visual awareness: this project has a dumb iPhone client, a low-rate preview stream, a persistent user intention, persistent displayed guidance, and a separate image-edit path of unmeasured latency. It therefore needs explicit observation freshness, shot-sized turns, conservative proactivity, and asynchronous generated visual guidance.

**Recommended product posture:** a quiet, interruptible shot coach—not an always-talking video-call companion. Keep the live preview visible; present one actionable adjustment at a time; distinguish “waiting for a stable view / checking latest preview / coaching / ready / generating guidance / stale or disconnected”; require a fresh-enough frame before precise spatial claims; and let capture, a changed intention, or an explicit user action cancel obsolete guidance. Voice interaction itself is outside the current product scope; the transferable lesson is preemption and honest state.

## Evidence standard

- **Documented** means an official product/help/developer source states the behavior.
- **Demonstrated** means it is visible or described in a first-party demonstration, but the source does not specify a stable product contract.
- **Inference** means a design implication drawn here. Inferences are not claims that the reference product implements the proposed camera-agent behavior.

## Findings

### 1. Interaction entry and persistent context

1. **Make visual availability unmistakable (documented precedent; qualified transfer).** In ChatGPT Advanced Voice on mobile, the user starts and stops live video with a camera button; voice can continue when video limits are reached. Gemini similarly instructs users to enter Live, tap the camera, point, and converse. This establishes that session connectivity and current visual access are separable. HelloCamera already owns the camera preview, so it does not need to copy those entry controls; internally it should distinguish socket connection, preview freshness, and whether the agent has evaluated a current frame. A future protocol extension should expose those distinctions without replacing the displayed instruction. Protocol v1 cannot show a separate stale-vision label, so its compatible behavior is to preserve guidance and avoid new visually precise claims until fresh evidence arrives. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Gemini Live camera help](https://blog.google/products-and-platforms/products/gemini/gemini-live-camera-how-to/)

2. **Carry one coaching objective through multiple visual turns (documented foundation; transfer with limits).** ChatGPT Voice works inside a chat, retains earlier messages, and lets users review the conversation; Google describes Project Astra as combining video and speech on a timeline and caching it for recall. Doubao’s official infrastructure account describes multimodal sessions rather than isolated image requests. For this agent, preserve the user-entered **intention** as the durable objective and the agent's current **instruction** as persistent displayed guidance, while keeping frame observations such as “subject was left of center” ephemeral and freshness-scoped. Never let a stale observation become persistent truth. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Google Project Astra engineering description](https://blog.google/innovation-and-ai/products/google-gemini-update-flash-ai-assistant-io-2024/) [Volcengine on Doubao’s multimodal transport](https://developer.volcengine.com/articles/7663051406903312422)

3. **Do not copy the open-ended “show me anything” home screen (inference; does not transfer).** The reference products are general assistants. Shot coaching has a known goal and a camera preview already occupying attention. Start with the persistent instruction and a compact “ready—show the setup” affordance; avoid mode menus, assistant-personality choices, and general-purpose prompt suggestions during composition.

### 2. Status and trust

4. **Expose a small semantic state machine, not a generic spinner (documented capability; inferred protocol-v2 UI).** OpenAI documents visible listening state, mute/stop controls, spoken/on-screen progress for longer work, and notices when sessions end or limits are reached. Volcengine explicitly provides agent task-status change messages so clients can react and maintain stability. The transferable pattern is honest, actionable state—not the exact reference UI. Candidate camera-coaching activities include `waiting_for_stability`, `evaluating`, `coaching`, `ready`, `generating_guidance`, `preview_stale`, `reconnecting`, and `failed`; collapse rapid states visually but retain them internally for recovery and evaluation. Displaying activity beside a persistent instruction requires the planned protocol-v2 activity channel. Protocol v1 has only one persistent text slot and cannot represent both cleanly. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Volcengine conversational-AI overview](https://www.volcengine.com/docs/82379/1393085?lang=zh)

5. **Make observation freshness visible when precise guidance depends on it (inference; proposed protocol-v2 behavior).** Google’s Live API sends video as individual images at no more than 1 fps, demonstrating that a “live” multimodal experience can actually be sampled vision. Doubao’s official infrastructure discussion says the gateway may choose frames, request a high-resolution image, or enhance a region, because a low-bitrate stream may not contain the detail being discussed. With this project’s low-rate preview, the runtime should distinguish “camera connected” from “latest frame evaluated,” bind advice internally to an observation identity, and avoid hallucinating continuity. A future client may surface coarse freshness/activity; protocol v1 can enforce freshness and drop stale results but cannot display an independent analyzed-frame badge. [Gemini Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities) [Volcengine on Doubao’s multimodal transport](https://developer.volcengine.com/articles/7663051406903312422)

### 3. Turn-taking and proactivity

6. **Translate barge-in into event preemption (documented precedent; qualified transfer).** OpenAI states that Live can listen and speak simultaneously and that users can interrupt; Volcengine documents automatic and manual interruption. The current camera product has no speech channel, so the transferable rule is that existing events—`intention_updated` and `user_capture`—and detected material scene/camera changes should supersede stale routine analysis and undelivered advice according to explicit freshness rules. Proposed `stop` and `skip` actions require protocol v2; they do not exist in protocol v1. Do not force the photographer to wait for obsolete work. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Volcengine conversational-AI overview](https://www.volcengine.com/docs/82379/1393085?lang=zh)

7. **Use task-aware turn evidence and provide a manual escape hatch (documented platform pattern; qualified transfer).** OpenAI warns that long pauses and overlapping input can produce false turns, while Volcengine offers automatic and manual triggering/interrupt methods. In a shoot, motion often means the user is carrying out an instruction—not requesting a new evaluation. Treat stable visual evidence as the automatic turn boundary. A protocol-v2 client should additionally support explicit `check_now`, `skip`, `pause`, and `resume` actions; protocol v1 has no equivalent other than changing the intention. Speech endpointing, wake words, and mute controls are outside the current scope. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Volcengine conversational-AI overview](https://www.volcengine.com/docs/82379/1393085?lang=zh)

8. **Be selectively proactive, not continuously conversational (documented capability; inferred policy).** Google’s Live API can be configured so the model decides not to answer irrelevant input; Gemini Live’s consumer positioning emphasizes natural back-and-forth. For shot coaching, proactivity should be event- or threshold-driven: update guidance when a requested check completes, a high-confidence material change persists across fresh samples, the user is about to capture, or recovery is required. Do not narrate every sampled frame or comment on transient motion. [Gemini Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities)

### 4. Latency masking and orchestration

9. **Expose a fast activity layer, but do not pretend slow work is instant (documented architecture; proposed protocol-v2 transfer).** OpenAI’s Realtime guidance treats low-latency sessions as persistent streams of events and recommends low reasoning effort when latency matters. Google exposes thinking-depth controls and defaults its current Live model toward minimal thinking for latency. Doubao’s official infrastructure account argues for separating low-latency, interruptible interaction from deeper work and for prioritizing the most valuable frame. Protocol v2 should acknowledge activity promptly (“Checking the latest preview”) while keeping the existing instruction visible, then deliver the smallest useful update; it should not fabricate certainty or require streamed prose. Under protocol v1, the runtime can preserve the instruction by omitting replacement text, but it cannot simultaneously expose a separate activity message. [OpenAI Realtime guide](https://platform.openai.com/docs/guides/realtime) [Gemini Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities) [Volcengine on Doubao’s multimodal transport](https://developer.volcengine.com/articles/7663051406903312422)

10. **Treat image editing as an asynchronous side job (inference; project-specific).** Image editing is a distinct, potentially slow tool call whose actual latency still needs measurement on the target setup. First give ordinary text/overlay guidance; offer generated visual guidance only when it adds value; and publish the result only if it still matches the current shot strategy and instruction. Protocol v2 should show `generating_guidance` independently while coaching and capture continue. A new shot should cancel or supersede **delivery**; the runtime may only discard a completed stale result unless the editor adapter proves underlying cancellation. Do not block the main coaching loop or show an indefinite generic spinner.

11. **Prefer latest-useful-frame semantics over buffering every frame (documented engineering pattern; transfer).** Doubao’s infrastructure source describes prioritizing audio, selecting valuable frames, dropping less valuable data for latency, and deciding when to request a high-resolution image. Google’s official Live API caps sent video frames at 1 fps. For this agent, keep at most the newest pending preview for routine coaching; preserve only frames tied to a capture, explicit comparison, or generated-reference job. If analysis falls behind, skip superseded previews rather than producing a backlog of late instructions. [Volcengine on Doubao’s multimodal transport](https://developer.volcengine.com/articles/7663051406903312422) [Gemini Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities)

### 5. Recovery

12. **Degrade by modality and preserve the objective (documented precedent; proposed redesign).** ChatGPT can continue a voice conversation after video becomes unavailable and keeps the same chat; Google’s Live API supports session context/resumption patterns. The current harness discards its task on disconnect even though the phone repeats the intention after reconnect. A v2 redesign should preserve bounded task state only when continuity can be established, mark prior visual evidence stale, and require a fresh evaluation before spatial guidance resumes; otherwise it should rebuild from the repeated intention. In either case, reconnection must not replay old coaching as if it were current. [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Gemini Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities)

13. **Make uncertainty and recovery actionable (documented risk; inferred UX).** OpenAI explicitly warns that background noise, overlap, and network conditions affect hearing; Google tells users to check important responses for accuracy; Doubao’s infrastructure account notes that latency jitter above one second can distort what the model receives and cause wrong or missing answers. Where the client can represent it, recovery copy should identify the failed channel and next action: “Preview connection is stale—reconnecting,” “That frame is too small to judge focus—move closer,” or “Generated guidance failed; coaching is still available.” Avoid silent fallback or a generic “Something went wrong.” [OpenAI Voice help](https://help.openai.com/en/articles/8400625-voice-mode-faq) [Gemini Live usage examples](https://blog.google/products-and-platforms/products/gemini/gemini-live-android-tips/) [Volcengine on Doubao’s multimodal transport](https://developer.volcengine.com/articles/7663051406903312422)

### 6. Visual guidance

14. **Ground directions in the visible preview and point when pointing is reliable (documented; qualified transfer).** Gemini Live officially highlights objects directly on the shared camera view. That is the strongest first-party precedent for spatial visual guidance. For a shot coach, overlays should be sparse and anchored—e.g., subject bounding box, horizon, directional arrow, or target region—and paired with one concise text instruction. Because the preview is sampled and overlays can drift, expire them when the analyzed frame is superseded; do not present them as live tracking unless local tracking actually exists. [Gemini Live visual guidance](https://blog.google/products-and-platforms/products/gemini/gemini-live-updates-august-2025/)

15. **Use one correction, confirmation, then progression (demonstrated/inferred; transfer).** First-party demos for Astra and Gemini Live center on pointing at a task, receiving an immediate grounded step, changing the scene, and continuing. That rhythm transfers better than a comprehensive critique: prioritize the largest composition/pose/lighting improvement, wait for a fresh frame, confirm briefly, then advance. This is an inference from demonstrations, not a documented Gemini coaching algorithm. [Project Astra](https://deepmind.google/models/project-astra/) [Gemini Live visual guidance](https://blog.google/products-and-platforms/products/gemini/gemini-live-updates-august-2025/)

16. **Generated “after” images are references, not real-time overlays (inference; does not directly transfer).** None of the reviewed first-party live-camera materials establishes slow generative image editing as part of the immediate perception loop. Label edited outputs as illustrative, tie them to the source frame and instruction, preserve the unedited preview, and avoid implying that the current scene already matches the generated result.

## Recommended camera-agent contract

| Area | Adopt | Avoid / applicability limit |
|---|---|---|
| Interaction | Explicit visual availability; persistent intention and instruction; live preview remains primary | General-assistant prompt carousel, personality theatrics, visual state implied by socket state |
| Status | Internal semantic states; protocol-v2 activity and freshness; separate generated-guidance status | Pretending protocol v1 can show status beside its one persistent text slot; claiming “seeing” while preview is stale |
| Turn-taking | Existing event preemption; settled evidence as an automatic turn; protocol-v2 check/skip/pause | Treating transient motion as a new evaluation request; allowing old work to survive capture or a changed intention |
| Latency | Immediate truthful activity where representable; concise coaching updates; latest-frame wins | Fake filler; queueing analyses for obsolete frames; blocking on image editing |
| Recovery | Freshness-scoped degradation; continuity checks; actionable retry | Assuming current reconnect retains desktop state; replaying stale advice after reconnect |
| Visual guidance | Sparse anchored overlay plus one instruction; expire on new frame | Dense annotations, unverified pixel precision, pretending sampled frames are continuous tracking |
| Proactivity | Only persistent, high-confidence, task-relevant changes | Continuous narration and unsolicited aesthetic judgments |

## What does not transfer from video-call assistants

- **Human-like social pacing as the primary goal.** Expressive voices and casual backchannels are marketing differentiators for general companions; a photographer needs brevity, timing, and control.
- **Continuous visual omniscience.** Official APIs and Doubao’s own infrastructure discussion reveal sampling, frame selection, and resolution tradeoffs. This project’s low-rate preview makes freshness explicitness mandatory.
- **Universal-assistant breadth and app/tool switching.** Calendar, search, shopping, and general screen sharing add little to a bounded shot-coaching loop and widen failure modes.
- **Multi-speaker/group-call and voice-turn assumptions.** The current product has no speech channel. Photographer-versus-subject addressing remains relevant to instruction wording, but speaker recognition and wake actions do not transfer.
- **Always-on proactive commentary.** Repeated unsolicited judgments are distracting and can be socially uncomfortable on set.
- **Synchronous generative visual feedback.** Editing latency is not yet measured. Treat generated visual guidance as independently tracked work; cancel or supersede delivery when stale without assuming the underlying editor call is abortable.
- **Exact copying of branded status animations or call chrome.** The evidence supports semantic states and controls, not any vendor’s visual treatment.

## Source-quality limitations

Doubao’s consumer UI is poorly documented on a stable, publicly accessible first-party page. The strongest accessible primary evidence is Volcengine’s documentation and its corporate developer-community engineering account; these establish infrastructure and supported patterns but do not fully document Doubao’s exact on-screen states or recovery copy. Official launch demos from all vendors are curated and do not quantify failure rates, end-to-end visual latency, overlay drift, or behavior under a low-rate client stream. Google Live API documentation is technically strong but describes a developer API, not necessarily the Gemini consumer app’s implementation, and it is explicitly preview/version-sensitive.

## Residual uncertainties and suggested validation

1. Test real devices to measure how ChatGPT Advanced Voice, current Doubao, and Gemini Live signal `listening`, `seeing`, interruption, weak network, and stale video; official materials do not expose a complete state diagram.
2. Measure transport jitter and end-to-end observation age on the project’s approximately 2 FPS preview stream. Use those measurements to calibrate freshness thresholds within protocol v1’s two-second overlay context limit.
3. The current iPhone renders normalized protocol overlays against the exact transmitted preview but does not track them locally. Validate how coarse the geometry and expiry must be to remain trustworthy as the scene moves.
4. Measure user tolerance for proactive cues during actual posing/capture. Compare explicit “check now” with automatic checks after settled evidence.
5. Establish cancellation and relevance checks for generated references, including whether an edit can be aborted or only discarded on completion.
