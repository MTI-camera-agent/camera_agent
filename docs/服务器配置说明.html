云端 GPU 服务器配置说明（模型常驻 / 租赁选型）

  • 版本：v1.1
  • 日期：2026-08-13
  • 推荐卡型：NVIDIA A100 80GB（单租户目标栈常驻；双租户见 §5）
  • 目的：固定云端模型分工与常驻显存 / 时延量级，供租赁选型；端侧模型不计入云端。
  • 原则：权重同时常驻，避免换入换出；MiniCPM-V 等放端侧。
  • 性质：工程估算。数字含权重 + 激活 / KV / ComfyUI 余量；以 nvidia-smi + 压测校准。

相关：development_workflow.md、flux_vllm_omni_service.md、01-MVP期-方案设计及计划.md。
消费级 RTX 5090 32GB 仅作附录候选，见 附录 A。

1. 结论（A100 优先）

问题 结论
优先租什么？ A100 80GB ×1：跑齐目标栈（9B Agent + Flux-9B + 4B 记忆 + 检测）仍有约 25–40GB 余量，适合生产单租户。
目标栈能否免换出？ 能。 合计常驻约 37–50GB（见 §4），远低于 80GB。
一张 A100 能否并发两套完整服务？ 不建议按两套完整隔离栈承诺。 2× 全栈 ≈ 75–100GB 易顶满。可行做法：两租户共享检测与/或 4B，或第二租户减配；稳妥则 双卡 / 两实例。
5090 32GB？ 附录候选：精简栈勉强，不含与 Agent 同步常驻的 4B 时仍紧；不作首选。

2. 模型分工（云端）

2.1 职责一览

角色 模型 精度（云端默认） 职责
统一 Agent / 理解 / 美学指令 Qwen3.5-9B FP8（A100）；可选 NVFP4（Blackwell） 预览帧 + Intent → 澄清问题；确认后输出 edit instruction 与 ShootingPlan；美学摄影能力由 Qwen3-VL-8B 整合训练并入，并微调 Agent
目标示意图 Flux.2-Klein-9B FP8 按 instruction 生成 reference_preview（目标参照图）
记忆归档 Qwen3-VL-4B FP8 用户摄影风格偏好、图像/视频描述等归纳；与 9B 并行，不阻塞 Agent 对话
人脸 InsightFace buffalo_l ONNX 检测 / 识别 / 对齐
通用打标 RAM++ FP16 开放集标签
Embedding SigLIP2 FP16 检索 / 风格·场景向量
端侧（不上云） MiniCPM-V 等 — 精调对比等本地环

现网开发机仍可能暂用 Qwen-Image-Edit-2511 / 外置 LLM；本说明的租赁目标栈以 Flux.2-Klein-9B 为示意图生成模型，2511 仅作迁移期冷备选，不计入 A100 默认常驻。

检测栈（可与上列并行）：buffalo_l ∥ RAM++ ∥ SigLIP2

要点：

  1. 对话主链路只依赖 Qwen3.5-9B（理解 → 问题 → instruction/Plan）。
  2. Flux 在 Plan/instruction 就绪后生成示意图，宜异步 PIP。
  3. 4B 后台归档，与 9B 同卡常驻、可并发推理，不得占用 Agent 请求队列到阻塞交互。
  4. 检测三件套 常驻，供人脸/标签/向量；时延远小于 VLM/生成。

3. 单模型显存（A100 常驻）

单位：GiB。常驻 = 权重 + 框架 + 中等上下文 / 单图激活（不含极端长视频）。

模型 精度 权重约 常驻约（A100） 备注
Qwen3.5-9B FP8 9–11 12–15 Agent + 视觉；KV 随 max-model-len 增加
Flux.2-Klein-9B FP8（DiT+TE 上 GPU） ~9 + TE 14–18 TE 卸 CPU 可降至 ~10–12，增首包时延
Qwen3-VL-4B FP8 5–6 6–9 归档短上下文可压到 ~6–7
buffalo_l ONNX ~0.3 0.5–1.5
RAM++ FP16 ~1–2 1.5–3
SigLIP2 FP16 ~0.8–1.5 1–2.5 so400m 量级
驱动 / 碎片 / 多进程余量 — — 2–3 多服务建议按 3 预留

检测三件套合计：约 3–5 GiB。

A100（Ampere）无原生 FP8 Tensor Core；FP8 权重仍显著省显存，计算路径常落到 BF16/FP16 kernel。显存表按 FP8 权重常驻计；若改 BF16 全精度，9B/Flux 约再涨一倍量级，不推荐。

4. 目标栈总显存（单租户 · A100）

组件 常驻约
Qwen3.5-9B FP8 12–15
Flux.2-Klein-9B FP8 14–18
Qwen3-VL-4B FP8 6–9
检测三件套 3–5
余量预留 2–3
合计 约 37–50 GiB
A100 80GB 剩余 约 30–43 GiB

用途建议：KV / 偶发高分辨率、Flux 与 9B 短时峰值、观测与小幅并发（如 4B 与 Agent 并行时各 1 路）。

变体 合计约 A100 判定
目标全栈（上表） 37–50 ✅ 首选
暂缓 4B 31–41 ✅ 余量更大
目标栈 + 2511 冷备同时常驻 55–70 ⚠️ 挤；默认勿双生成常驻

5. 双服务并发（同一张 A100 80GB）

「两套服务」默认按隔离进程、权重不共享估算。

配置 合计约 判定 说明
2 × 目标全栈（9B+Flux+4B+检测） 75–100 ❌ 易 OOM
2 ×（9B+Flux+检测），共享 1×4B 68–85 ⚠️ 卡上限；需限 batch / len
2 ×（9B+Flux+检测），共享 4B + 检测 62–75 ⚠️～✅ 较现实的同卡双租户
1 × 全栈 + 1 × 仅 Agent/检测（无 Flux） 50–65 ✅ 第二实例不做示意图
2 × 独立全栈 — ❌ 改 2× A100 或两台实例

推荐表述：A100 80GB 优先保障单租户目标栈 + 4B/Agent 并行；双租户同卡需共享轻量模型或减配，否则双卡。

示意切分（共享检测 + 共享 4B）：

A100 80GB
├── shared: Qwen3-VL-4B (~7) + 检测 (~4)
├── tenant-A: Qwen3.5-9B (~13) + Flux-9B (~16)
└── tenant-B: Qwen3.5-9B (~13) + Flux-9B (~16)
    合计 ≈ 69 GiB（紧；生产需压测）

可用 MIG 切两块硬隔离，灵活性下降。

6. 推理时延（A100 · warm）

条件：权重已常驻；单请求；预览帧长边 ~1280 或示意 1024²；FP8 权重。A100 单请求时延与高端消费卡同量级，吞吐与稳定性更好。

调用 P50 量级 备注
Qwen3.5-9B：理解 / 澄清（帧+Intent） 1–3 s 视输出长度；多轮追问按轮累加
Qwen3.5-9B：确认后 instruction + Plan 1–3 s 结构化输出略长时可到 ~4 s
上述两阶段串行（典型慢路径） 2–6 s 不含外置 API
Flux.2-Klein-9B 示意图（蒸馏 ~4 step） 2–5 s 本仓 Klein-4B@3090 warm 编辑 ~3.6 s 可作下界参考
Qwen3-VL-4B 记忆归档（后台） 0.5–1.5 s 不计入对话关键路径
buffalo_l 20–80 ms
RAM++ 50–200 ms
SigLIP2 30–100 ms

端到端（用户可感知）：

阶段 组成 量级
对话澄清 → Plan 仅 Qwen3.5-9B 约 2–6 s
示意图 PIP Flux 异步 +2–5 s（不挡对话）
记忆归档 4B 异步 不阻塞
检测增强 三件套并行 +0.1–0.3 s

冷启动（应开机预热，勿走在线路径）：9B / 4B 各约 20–60 s；Flux/ComfyUI 首次可达 1–3 min。

7. 租赁配置建议（以 A100 为中心）

档位 GPU 场景
首选 A100 80GB ×1 单租户目标全栈常驻；9B∥4B 并行
双租户稳妥 A100 80GB ×2（或两实例） 各跑全栈，故障域隔离
同卡双租户试验 A100 80GB ×1 仅共享 4B/检测减配后压测通过再上
更高吞吐 H100 80GB 原生 FP8；单价更高
消费级候选 RTX 5090 32GB 见附录 A，非首选

系统侧：内存 ≥ 128GB；NVMe ≥ 500GB（多套 FP8）；驱动/CUDA 匹配 vLLM + ComfyUI；systemd 预热 Agent、Flux、4B、检测服务。

量化：A100 上 VLM/生成默认 FP8 权重；勿按 BF16 全量预留。

8. 部署约束

  1. 常驻：在线路径禁止卸权重；OOM 时先降 max-model-len / 并发，再升配。
  2. 主对话只走 Qwen3.5-9B；Flux 与 4B 异步，队列隔离，避免生成/归档占满抢占对话。
  3. 示意图生成默认 Flux.2-Klein-9B；勿与 2511 双常驻。
  4. MiniCPM-V → 端侧，不占 A100。
  5. 上线压测：9B 对话、Flux 示意、4B 并行归档、检测三件套；记录 P50/P95 与显存峰值。

附录 A. 候选参考：RTX 5090 32GB

非租赁首选。桌面 5090 标称 32GB；可用预算按约 30GB（扣驱动/上下文）。本地开发文档中的「约 24GB」可能是观测/碎片后数值，不改标称容量。

A.1 能否跑目标栈？

组合 合计约 32GB 说明
9B FP8 + Flux FP8 + 检测 30–36 ❌ / 极紧 几乎无 4B 余量
9B NVFP4 + Flux FP8 + 检测 26–33 ⚠️ 精简单租户下限；限 KV / batch=1
上表 + 4B 常驻 33–41 ❌ 与「4B∥Agent」目标冲突
目标全栈（同 §4） 37–50 ❌

结论：5090 适合开发或精简演示（NVFP4 + Flux + 检测，4B 卸掉或端侧代劳）；不能满足「A100 目标全栈 + 4B 与 Agent 同步常驻」。双租户同卡不可行。

A.2 5090 时延量级（参考）

与 §6 同量级（warm 单请求）；NVFP4 在 Blackwell 上 VLM 吞吐可优于 A100 FP8 权重路径，但显存天花板限制并发与 4B 常驻。

A.3 何时可考虑 5090

  • 预算优先、仅单用户开发；
  • 接受暂缓云端 4B，或记忆改 CPU/更小模型；
  • 接受偶发串行 / 更紧的 gpu_memory_utilization。

生产与「双模型并行不阻塞」仍优先 A100 80GB。
